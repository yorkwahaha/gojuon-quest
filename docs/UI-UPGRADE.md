# 版面升級建議

狀態：設計建議，尚未實作新版視覺。這次只能檢視 HTML／CSS；瀏覽器連線主機不可用，原生 Chrome 也持續回報視窗最小化，沒有取得可靠截圖。以下是原始碼診斷，不作畫面評分或視覺通過宣告。

## 先處理的三個問題

1. **字體與輪廓重複柔化**：標題、內文均使用 Zen Maru Gothic／M PLUS Rounded 1c；CSS 有 66 處 `border-radius`，主容器 20px、按鈕 12–18px、彈窗 24px，標籤與資訊籌碼多用膠囊形。題目、導航、資源數字容易具有相同的外觀重量。
2. **色彩角色分散**：深紫底上同時使用金、紅、青、紫、綠與多層放射漸層。金色同時表示主要操作、金幣、獎勵與強調文字，難以讓玩家立即辨識操作優先級。
3. **首頁資訊與裝飾爭奪注意力**：英雄圖、漂浮假名、玩家面板、每日橫幅、任務橫幅、模式卡片連續出現。1024px 以下又把英雄圖排到文字之前，使行動版的開始操作更往後。

## 四種不同的方向

| 方向 | 核心與情緒 | 資訊與構圖 | 字體、形狀與材質 | 代表互動與轉場 | 代價 |
|---|---|---|---|---|---|
| A．假名攻略手冊（建議） | 像翻開一本清楚、有進度感的日語攻略；安定、有成就感 | 左側大假名與「聽音挑戰」，右側窄玩家摘要；每日任務是單行目錄；模式改成編號清單 | 深墨底、暖紙面、朱紅強調；直立黑體；直角分隔線；假名字磚最多 6px | 選字磚像蓋上字印；下一題沿同一基線推進 | 需要減少現有裝飾，英雄圖降為側邊插圖 |
| B．漫畫扉頁／戰鬥分鏡 | 把角色名與招式拼成一格漫畫；俐落、有爆發力 | 左上標題、右下主要操作，非對稱斜切分鏡；玩家數字進入頁邊欄 | 黑白大面積、單一赭金；粗黑標題、正常內文；直角與少量斜切 | 答對時出現一格速度線，答錯用刪改筆畫 | 長文字與小螢幕易擁擠；需嚴格限制斜切與特效 |
| C．假名修行道場 | 每題是一段修行，進度像印章簿；專注、沉著 | 中央主題、側邊縱向修行階梯；收藏像打開一冊實體印譜；首頁直接呈現今日一課 | 亞麻白、炭黑、暗朱紅；黑體內文配少量明體章節名；細線、紙張與印記 | 字磚沿書寫位置落印；完成一課留下日期印章 | 與現有高彩度招式演出差異大，需要重整演出素材 |
| D．聲音波形拼字軌道（實驗） | 讓「聽到→拼出」成為版面本體；探索、解謎 | 首頁是一條聲音到字磚的軌道；題目占畫面主軸，得分沿軌道邊緣顯示 | 石墨灰、米白、單一銅橘；清晰黑體；方形字磚、刻度與連線，少用面板 | 播放讀音時游標沿軌道移動；完成排列才接通終點 | 需另設五十音表與任務的閱讀布局；無語音使用者需保留完整文字入口 |

四個方向都以假名、讀音、排列或修行進度作為辨識特徵，避免只換色卻保留相同卡片格局。

## 建議採 A：可直接交付實作的規格

### 色彩、字體與框形

| 項目 | 建議 |
|---|---|
| 頁面背景 | 墨黑 `#171B21`，取消首頁三層彩色光暈與星屑背景 |
| 主要閱讀面 | 暖紙 `#F3EDE2`；深字 `#232831`；次要字 `#535B66` |
| 主要操作 | 暗朱紅 `#A33B32` 配暖紙色字；每個主要區域只留一個實心操作 |
| 資源 | 赭金 `#C69749` 只用於金幣、獎勵數字與細線，不做大面積發光底 |
| 答對／答錯 | 答對用 `#286451`＋勾號；答錯用朱紅＋叉號與文字，不能只依賴顏色 |
| 字體 | 優先 `system-ui, "Yu Gothic", "Microsoft JhengHei", sans-serif`；先移除兩套圓體載入，不新增付費字體或套件 |
| 字級 | 首頁主標 40–56px、區標 24–28px、內文 16px、輔助字至少 13px；字磚 28–36px。行動版主標 30–36px |
| 字重 | 內文 400、標籤 600、主要標題 700；停止全頁普遍使用 900 |
| 邊角 | 大容器 0px、按鈕 4px、可操作假名字磚 6px；圓形僅保留愛心語意、金幣與設定開關 |
| 表面層級 | 頁面／閱讀面／浮層三層即可；主要內容以間距和分隔線分組，不再每段加一個框 |
| 間距 | 以 8px 為基準；區塊間 24–32px、區內 12–16px；優先對齊文字基線 |
| 圖示 | 沿用現有 SVG，統一筆畫；移除每個模式圖示背後的彩色圓角底 |

### 形狀與互動約束

1. 三個形狀規則：閱讀區直角；操作用 4px 角；假名字磚用 6px 角。禁止膠囊式模式卡、雙層圓角框，以及每個圖示套一個圓角容器。
2. 主視覺手勢是一條從大假名延伸到字磚的水平基線；玩家資訊置於較窄側欄，形成刻意不對稱。
3. 主要互動是字磚「落印」：120–160ms 位移，使用現有放置音效；下一題沿基線滑入，180–220ms，簡單 ease-out。
4. 答對用單次印章與文字；答錯用叉號、說明與小幅位移。緊迫感只在限時模式剩餘 10 秒顯示時間刻度與紅色提示。
5. 進度透過編號與細進度線呈現。連擊、金幣、升級每次最多一種主演出；升級通知等待招式演出結束。尊重減少動態偏好，操作結果不得等待裝飾動畫。

### 畫面與元件

| 畫面 | 結構／保留項目 | 刪除或合併 |
|---|---|---|
| 首頁 | 大假名＋一個「開始聽音挑戰」；窄玩家摘要；每日任務一列；其餘模式編號清單 | 背景漂浮字、滿版星屑、四張同權重模式卡；個人數據不再各自包框 |
| 作答 | 讀音與提示→空格→字磚→操作，固定閱讀順序；得分／愛心退到上緣 | 多層線索框、過多膠囊標籤；將作品、難度合成一行輔助文字 |
| 五十音表 | 對齊的字格與行列標示；當前字以底線／印記呈現 | 每格不同陰影；拗音行與清音行分區，不能假裝使用相同母音列 |
| 任務 | 任務名稱、進度線、獎勵、領取按鈕構成列表 | 每列外框與圖示底板，保留可領取／進行中／已完成的文字狀態 |
| 收藏 | 保留卡片外形，稀有度用文字、細邊線與小印記 | 膠囊標籤與重複光暈；卡片是少數有框的內容 |
| 結算 | 主要成果→得分明細→再玩／首頁；移轉鍵盤焦點並可返回觸發點 | 每個統計值的獨立圓角底板 |

不需要新圖片即可先做第一輪；現有英雄 SVG 可縮成頁邊圖，既有語音與音效維持。主要重用按鈕、字磚、資料列、進度線與彈窗五種元件，不另加 UI 套件。

### 響應式與驗收

1. 桌面 1440×900：主操作與最近進度在首屏，標題、字磚是兩個明確視覺焦點。轉為灰階、縮至 25% 時，仍能辨識主操作與題目區。
2. 行動版 390×844／窄版 320px：把側欄移到開始按鈕後，取消英雄圖置頂；不橫向溢出，首頁主要操作不得被插圖推到首屏之外。
3. 點擊目標至少 44×44px；日文與繁中、最長角色名稱與全部字磚都不得裁切。長答案可換行但固定符號不能脫離對應字序。
4. 實測文字對比：內文至少 4.5:1，大字至少 3:1。切換語言、鍵盤焦點、答案空白／已選／答對／答錯、愛心歸零、限時 10 秒、結算、設定與抽卡都需截圖。
5. 下一輪應提供首頁、作答、五十音表、結算四畫面的桌面／手機前後對照，檢查辨識度、層級、構圖、一致性、玩法連結、世界連結、字體、易讀性、狀態、情緒、動態與視覺節制；沒有截圖前不給分。

優先順序：**P1 改字體／首頁閱讀順序／收斂主色 → P2 移除多餘框、統一角度與列表 → P3 重整演出與進度印章**。B 是更強烈的漫畫方案，D 是高風險實驗；目前建議先用 A 完成可驗收的第一輪。
